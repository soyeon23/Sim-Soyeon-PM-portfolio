Overview

R&D 과제 수행 중 반복되는 연구행정 법령 질의응답(국가연구개발혁신법 관련 규정·지침 등)을 매번 문서를 직접 찾아야 하는 비효율을 해결하기 위해, PDF·HWP 매뉴얼·법령 문서를 학습한 보수형 RAG 챗봇을 직접 개발하고 실무에 적용했습니다. 근거 없이 답변하지 않으며, 모든 출처(문서명·조문·페이지)를 명시하는 것을 핵심 원칙으로 설계했습니다.

Domain Problem → Knowledge Architecture → RAG → Prototype → Workflow Integration

  • 반복 질의응답 비효율을 문제로 정의하고, RAG 아키텍처로 해결 방향 설계
  • 질의 유형(일반 토픽·페이지 조회·조문 조회·비교형) 분류 및 라우팅 로직 설계
  • Qdrant 벡터 DB 기반 하이브리드 검색(의미 검색 + 텍스트 검색) 구현
  • 법제처 MCP·HWP MCP 연동으로 문서 파싱 커버리지 확대
  • Claude Code를 활용한 4-에이전트(PM·Backend·Frontend·Scout) 개발팀 구조로 빠른 반복 개발

Overview

여러 사람의 일정을 맞추는 과정에서 카카오톡으로 날짜를 주고받고, 중간 장소는 따로 지도 앱을 열어 찾아야 하는 분산된 불편함을 직접 경험하면서 '일정 조율 + 중간 장소 추천'을 한 곳에서 해결하는 웹서비스를 기획·개발했습니다.

회원가입 없이, 앱 설치 없이 링크 하나로 바로 사용할 수 있도록 진입 장벽을 낮추는 것을 핵심 설계 원칙으로 삼았습니다.

  • Supabase로 모임 데이터 관리 및 실시간 응답 수집 구조 설계

평균 점수 중심 → 변동성·패턴 누적 기반 위험 신호 임계치 설정

04 Insight

위험 신호 → 운영 판단 → 대응 액션으로 이어지는 TO-BE 플로우

05 Output

운영 리스크 판단 프레임, 대응 프로세스 플로우차트

Overview

교육 서비스의 리뷰·평점 데이터를 사후 결과 지표가 아닌 '운영 개입을 놓친 위험 신호'로 재정의하고, 운영 중 발생할 수 있는 리스크를 조기 감지하여 선제적으로 대응할 수 있는 운영 판단 프레임을 설계하였습니다.

주요 역할

  • 리뷰·평점 기반 운영 리스크 유형 정의 및 판단 기준 설계
  • 위험 신호 → 운영 판단 → 대응 액션으로 이어지는 의사결정 구조 설계
  • [PM-운영-콘텐츠] 조직이 공통으로 활용 가능한 리스크 대응 프로세스 정립

주요 결과

전환 사후 인지 → 사전 감지
수립 변동성 기반 위험 판단 기준
설계 TO-BE 의사결정 플로우

향후 발전 계획

본 프로젝트를 통해 리뷰·평점은 단순한 만족도 지표를 넘어 운영 개입 실패를 조기에 알려주는 선행 신호로 활용될 수 있음을 확인하였습니다. 향후에는 리뷰·평점 외에도 문의 유형, 이탈 패턴, CS 로그 등 다양한 운영 데이터를 결합하여, 리스크 수준별 우선순위를 판단하고 개입 강도를 조절하는 전사 공통 리스크 감지 및 대응 모델로 확장할 수 있습니다.

분석 방법: 리뷰·평점 변동성 패턴 분석, 위험 신호 임계치 설정
